# Product

> Parent: [README](../../README.md)

What Su-Su does and why. [PLAN](PLAN.md) is the authoritative spec; the other two documents explain how it got there and are read only when a decision is questioned.

| Document | Purpose | Read when |
|---|---|---|
| [PLAN](PLAN.md) · 项目方案 | The product spec: features, services, windows, plugin API, data, flows, languages, updates, milestones | You need to know what to build |
| [RECORD](RECORD.md) · 方案记录 | Decision log (D-xx), rejected options, research and measurements | You want to know why something was decided, or to reverse it |
| [REVIEW](REVIEW.md) · 技术方案评审 | Findings R01–R13 of the third-version review and where each was resolved | You trace a design change back to its review finding |

How the product is designed visually is in [Design](../design/README.md); how it is implemented is in [Architecture](../architecture/README.md).
