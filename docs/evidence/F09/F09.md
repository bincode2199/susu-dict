## Scope and contracts

- **F09.1:**
  - **Classifier:** `TextForms` implements the PLAN 6.1 rule. `DictionaryEntries.IsEmpty` defines a legal empty entry; a failure is always an error, never an empty entry.
  - **Endpoints:** P-T07 `plugins/youdao` translates through `/api` and looks up dictionary entries through `/v2/dict` (`ec`/`ce`), because v3 removed dictionary data from `/api`.
  - **Secrets and grants:** secrets `appKey` and `appSecret` are granted as `appKey` → `query:appKey` + `query:sign` and `appSecret` → `query:sign`. Signing uses the existing broker `digest` primitive with no broker change: the plugin passes the public parts (truncated input, salt, curtime), and the host writes the sha256 into the reserved `sign` field. The plugin never sees either secret.
  - **Limits and errors:** 5000 code points. Errors map as follows: 108/110/111/202/203/205/206 → auth; 401 → quota; 411/412 → rate_limited; 102 → unsupported_language; 301–304 → network; anything else → bad_response. Errorcode 120, or a successful reply with no content, is an empty entry.
  - **Dictionary model:** Youdao output maps into the existing `DictionaryResult`, with no contract change; only https audio links are kept. Web phrases and pinyin are not mapped (the contract has only us/uk phonetics).
  - **Unconfirmed against the real service:** signing fields in the query with `q` in the form body, and the `/v2/dict` nesting (the parser also accepts the old `/api` names).
  - **Spec gap:** the sandbox has no `crypto` or `URLSearchParams`, though PLAN 4.3 lists `crypto`. Carried to F16.
