## Scope and contracts

- **F09.1:**
  - **Classifier:** `TextForms` implements the PLAN 6.1 rule. `DictionaryEntries.IsEmpty` defines a legal empty entry; a failure is always an error, never an empty entry.
  - **Endpoints:** P-T07 `plugins/youdao` translates through `/api` and looks up dictionary entries through `/v2/dict` (`ec`/`ce`), because v3 removed dictionary data from `/api`.
  - **Secrets and grants:** secrets `appKey` and `appSecret` are granted as `appKey` → `query:appKey` + `query:sign` and `appSecret` → `query:sign`. Signing uses the existing broker `digest` primitive with no broker change: the plugin passes the public parts (truncated input, salt, curtime), and the host writes the sha256 into the reserved `sign` field. The plugin never sees either secret.
  - **Limits and errors:** 5000 code points. Errors map as follows: 108/110/111/202/203/205/206 → auth; 401 → quota; 411/412 → rate_limited; 102 → unsupported_language; 301–304 → network; anything else → bad_response. Errorcode 120, or a successful reply with no content, is an empty entry.
  - **Dictionary model:** Youdao output maps into the existing `DictionaryResult`, with no contract change; only https audio links are kept. Web phrases and pinyin are not mapped (the contract has only us/uk phonetics).
  - **Unconfirmed against the real service:** signing fields in the query with `q` in the form body, and the `/v2/dict` nesting (the parser also accepts the old `/api` names).
  - **Spec gap:** the sandbox has no `crypto` or `URLSearchParams`, though PLAN 4.3 lists `crypto`. Carried to F16.
- **F09.2:**
  - **Lookup order:** for a word-form input with `youdao/dictionary` enabled and ready, the card looks the word up first. The lookup runs inside the same attempt (same lease, deadline and cancel) as a translate call. Only a legal empty entry is followed by one translate, sequentially. A lookup error stays the card's error, and translate never replaces it.
  - **Contract:** `CardSnapshot.Entry` is a `DictionaryEntryView` (plain text only); `CardSnapshot.Dictionary` is true iff `Entry` is set. Phonetics carry an opaque `AudioId` (https links only), and `TranslationSession.ResolveAudioAsync(id)` resolves an id only while the current generation's card still shows that entry.
  - **Settings:** the dictionary reuses Youdao's credentials and grants, and both Youdao services are off by default. Lookups are counted under the usage metric "dictionary". Enabling the dictionary while Youdao translate is off gives no card.
- **F09.3:**
  - **Rendering:** `DictionaryEntry.vue` renders the entry as text only.
  - **Projections (`ui/src/components/dictionary.ts`):** `entryPlainText` is the copy text (word; `英 /ipa/  美 /ipa/`; one line per part of speech; forms; examples; never audio ids). `entryVocabProjection` returns `{word, lang, source, phonetics, meanings, forms, examples}` for F15.
  - **Actions:** read-aloud and favorite are disabled with a tooltip until F10/F15, and appear on the dictionary card only.
  - **Audio port for F10:** `IDictionaryAudioSource.FetchAsync(audioId, ct)` returns `Ready(FileLease, Mime, Length)`, `Refused(UnknownOrStale | InvalidLink | OriginNotDeclared | RedirectOutsidePolicy)` or `Failure(kind)`. The implementation is `DictionaryAudioFetcher`: one GET with no credentials, restricted to the service's declared origins on every hop, audio MIME types only. F10 wires it into `Program.cs`.
  - **Coordinator fix `d6868fb`:** plugin `$http` redirects are now checked against the call's granted origins on every hop (PLAN 4.5 item 3, S06). Before, a request without credentials could be redirected to any public https origin.
