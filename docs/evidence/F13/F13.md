## F13.1 · Loopback source for the F12 recorder

Conclusion: system audio is recorded by the existing F12 recorder with a second device source; no second recorder exists. The UI, hotkey and entry are F13.2.

| Piece | Where |
|---|---|
| `AudioSourceKind { Microphone, SystemLoopback }`; `IRecordingSession.Source`; `RecordingResult.Source` and `IncludesOwnPlayback` (true for loopback: the UI notice that system sound includes Su-Su's own TTS) | `src/Susu.Abstractions/AudioCapturePorts.cs` |
| Start errors for loopback: `loopback.noDevice`, `loopback.denied`, `loopback.failed` (`RecordingStartResult.Failed(failure, source)`) | same |
| `AudioCaptureCoordinator(devices, files, clock, limit, source)`: the same coordinator and session; 10-minute captured-time limit unchanged | `src/Susu.Jobs/AudioRecording.cs` |
| `WasapiMicrophone.SystemLoopback()`: default render endpoint (eRender, eConsole), `AUDCLNT_STREAMFLAGS_LOOPBACK`, 16 kHz mono PCM via AUTOCONVERTPCM; the microphone is never opened | `src/Susu.Windows/Audio/WasapiMicrophone.cs` |

Behaviour:
- **Silent output.** Loopback delivers no packets while nothing plays, so the stream fills idle time (20 ms or more) with silent blocks. The timeline advances, the existing silence notice (`RecordingLevel.Silent`, `RecordedAudio.Silent`) is used, and it is not read as sleep. An idle gap of more than 1 s (a real stall) is not filled, so the recorder still sees it and reports Sleep.
- **Switch or removal.** A changed default output ends the stream with `DefaultChanged` (removal: `DeviceRemoved`) -> Interrupted with that reason, the captured part kept, no reopen on another device.
- **No output device.** `HasDevice()` is false and start returns `loopback.noDevice` with no file.

Tests (`tests/Susu.Tests.Unit/LoopbackRecordingTests.cs`, filter `*LoopbackRecordingTests`):

| Case | Test | Kind |
|---|---|---|
| REC04 loopback, mic never used, own-playback flag | `Loopback_records_the_output_device_and_never_touches_the_microphone`, `Microphone_results_do_not_carry_the_own_playback_notice` | fake device |
| REC04 no output | `No_output_device_is_a_loopback_error_with_no_file` | fake device |
| REC04 silent output | `Silent_output_shows_the_silence_notice_and_is_not_an_interruption` | fake device |
| REC03 switch / removal | `Output_switch_or_removal_interrupts_keeps_the_part_and_never_follows` (2 cases) | fake device |
| 10-minute limit rule | `Loopback_stops_at_the_captured_duration_limit` (1 s limit; `MaxDuration` is 10 min) | fake device |
| REC04 real | `Real_loopback_captures_a_tone_played_through_the_default_output`: idle output records without interruption, then a 440 Hz tone played with `WasapiAudioSink` is captured non-silent | **real** WASAPI on this VM ("Remote Audio" output); skips with a reason when no render endpoint exists |

Not covered for real: a real default-output switch or device unplug while recording (fake only), and sleep. Own-TTS capture is shown with a played tone, not with SAPI speech.

## F13.2 · System audio in the voice window

Conclusion: system audio is the F12 voice window with a second source; there is no second window, recorder, ASR job or translation pipeline. A system-audio hotkey or tray item opens the same window in `systemAudio` mode and the same `AsrJob` and translation session handle the result.

| Piece | Where |
|---|---|
| `VoiceView.Source` (`microphone` / `systemAudio`) and `OwnPlayback`; the page picks its title and wording from them | `src/Susu.Contracts/UiViews.cs`, `protocol/generated/ui.ts` |
| Shell: `SystemAudioCapture` port; `OpenVoice(source)`; start uses the capture and the feature of the current source; default error code per source; own hotkey `audioTranslate` shown in the window; tray status and open rules per source | `src/Susu.Ui/Voice.cs`, `src/Susu.Ui/Shell.cs` |
| Entry: `system-audio` feature registered Available with `Capability.Asr` (greyed with `feature.noService.asr` like Voice); `SystemAudioCapture = new AudioCaptureCoordinator(WasapiMicrophone.SystemLoopback(), files, clock, null, AudioSourceKind.SystemLoopback)` | `src/Susu.Host/Program.cs` |
| Page: `vt()` takes `voice.sys.*` text when the source is system audio and falls back to the shared text; own-playback notice; `loopback.*` error text | `ui/src/windows/VoiceWindow.vue`, `ui/src/locales/i18n.ts` |

Behaviour:
- **One window, two sources.** With no recording running, the other source's hotkey or tray item empties the window and switches the source. With a recording running (also minimized), it only brings the window forward; the running source stays.
- **Notice.** `ownPlayback` is true for system audio and the page shows the note in every phase of that window (idle, recording, paused, transcribing, result, interrupted).
- **Interruption.** Same flow as F12.3: part kept, transcribe recorded or record again; "record again" uses the loopback again.

Tests: `*VoiceWindowTests` (7 new, 37 total), `*LoopbackRecordingTests` (1 new, 9 total), `ui/tests/f13-system-audio.test.ts` (10 new). Full suite 1387 total, 1381 passed, 6 skipped, 0 failed; vitest all pass; `vue-tsc --noEmit` clean.

Not done / open:
- The tray icon tooltip says "录音中 / Recording" for both sources (no source name).
- The dev-preview host fixture still shows the system-audio tray item as in development.
- The own-playback note does not detect whether Su-Su is actually speaking at that moment; it is always shown.
- No real end-to-end run (real output device + real ASR service); A08 system-audio sample pending.
