Behaviour and decisions:
- Identity is (lang, normalized text): NFC, plus case folding for `en*` only; `display_text` keeps the first original spelling. Content identity is canonical JSON (key order and whitespace ignored).
- Entry write and one outbox row per target commit in one writer transaction; fault stages `favorite:entry` and `favorite:outbox` prove nothing survives a crash. Same (entry, revision, target) keeps its operationId; a changed content bumps `revision` and queues new rows, and unsent rows of older revisions become `Cancelled`.
- Unfavorite sets `deleted_at` and cancels only Pending/RetryWait rows; Sending, Succeeded, Uncertain rows are untouched and nothing remote is deleted. Re-favorite restores the entry, and revives cancelled rows with the same operationId.
- Added state `Cancelled` beyond the ARCHITECTURE 8.3 list (Pending, Sending, Succeeded, RetryWait, Uncertain, Failed) to represent "stopped before sending"; ARCHITECTURE was not edited.
- `Claim` takes the oldest due Pending/RetryWait row of one target to Sending (attempts + 1); `Complete` only affects Sending rows. `RecoverInterrupted` turns Sending into Uncertain so a restart never resends.
- Existing DATA03 test (`Failed_migration_and_rollback_to_an_older_app`) was moved from fictional version 2 to 3 because schema 2 is now real.

Evidence: full suite 1564 total, 1557 pass, 0 fail, 7 skipped (same skips as before); 12 new tests; DATA05 (dedupe, case, targets independent, unfavorite keeps remote, atomicity) and the storage half of DATA06 (Sending to Uncertain, not claimable) are covered by unit tests only. ## F15.2 · Export generators and file transaction (done 2026-10-01)

Scope delivered: Eudic txt, CSV and Anki apkg generators over one snapshot, one file transaction, a recovery record. No SetVocab UI or host export command yet (F15.4); no sync plugins (F15.3).

| Item | Where |
|---|---|
| Pure generators: `EudicTxt`, `Csv`, `Apkg`, text cleaning, projection parse | `src/Susu.Storage/VocabFormats.cs` |
| `VocabExporter` (snapshot, only-new, transaction, `Recover()`) | `src/Susu.Storage/VocabExporter.cs` |
| Schema 3: `vocab_exports.path` for recovery | `src/Susu.Storage/Database.cs` (`SchemaVersion = 3`) |
| Host runs `Recover()` at start-up after `RecoverInterrupted()` and logs `vocab.export-recovered` | `src/Susu.Host/Program.cs` |
| Tests (15) | `tests/Susu.Tests.Unit/VocabExportTests.cs` (`--filter-class "*VocabExportTests"`) |

Behaviour and decisions (the specs name none of the format details):
- One `IFavorites.List` call is the frozen snapshot; later edits do not leak in and stay "new". Deleted entries are never exported.
- Txt: one word per line, UTF-8 no BOM, LF, deduped ignoring case. CSV: RFC 4180, CRLF, UTF-8 BOM for Excel, cells starting with `= + - @` get a `'` prefix; the content choice (definitions/phonetics/examples) drops columns. Control characters removed, lone surrogates become U+FFFD, fields cut at 20,000 chars and reported in `Issues`.
- apkg: zip with a legacy schema 11 `collection.anki2` (one note type, one deck, no media), guid derived from the entry id so re-export updates; sort field and checksum computed as Anki does.
- Transaction: record written Pending with its (entry, revision) items and file SHA-256, then temp file in the target folder, flush, atomic move, then Succeeded. Disk full or IO failure: no target change, record Failed, items dropped, retryable flag set for disk full. Crash after the move: `Recover()` finds the file by hash and marks Succeeded (no second copy); no file or other hash: Failed; temp leftovers deleted.
- "Only new" is per format and compares (entry, revision) with Succeeded exports; an unchanged set returns `export.nothingToExport`.
- Existing test `Failed_migration_and_rollback_to_an_older_app` moved from fictional version 3 to 4 (schema 3 is real).

Evidence: full suite 1579 total, 1577 pass, 0 fail, 2 skipped (machine-dependent audio skips). Apkg tests unzip it, open the SQLite file and check `col`, notes, cards, checksums and sort fields. Adversarial: quotes, newlines, emoji ZWJ, RTL override, NUL and BEL, lone surrogate, 100k-char field, formula cells, 5000 entries in all three formats, disk-full stream, crash after record, before move and after move.
Not executed: real Anki import (no Anki installed here, so compatibility with a named Anki version is unverified; ARCHITECTURE requires it, open item for acceptance); Eudic import; Excel opening the CSV; the in-process fault tests unwind through `finally`, so a true process kill is simulated by planting the leftover files.

## F15.3 · Sync packages and host sync worker (done 2026-10-01)

Scope delivered: P-V01 AnkiConnect and P-V02 Eudic packages, the plugin-side target adapter, and the host worker that consumes the F15.1 outbox. No SetVocab UI, no host command and no start-up wiring of the worker (F15.4 adds targets, settings and the star button); nothing is sent until a target instance exists.

| Tests: 13 worker tests (`--filter-class "*VocabSyncWorkerTests"`), 22 plugin tests through the real sandbox (`--filter-class "*VocabPluginTests"`) | `tests/Susu.Tests.Unit/VocabSyncWorkerTests.cs`, `VocabPluginTests.cs` |

Behaviour and decisions:
- Anki: the note type `Su-Su` (fields Word, Phonetic, Definition, Example, Source, SusuId) and the deck are created when missing. Notes are found by `SusuId` (the entry id), so lookup, update and "was it added" are by id; the operationId is a tag. A new revision updates the same note. `addNote` runs with `allowDuplicate: false`; a duplicate answer means the word is already there and is reported as found (no second note). The optional key (`useApiKey`) is written by the broker into `/key`; nothing is sent when the option is off.
- Eudic: lookup is `GET .../studylist/word/{word}?language=`; upsert is lookup, then `POST .../studylist/word` with `category_ids` when a word list is chosen (found and no list chosen: nothing written). Languages en, fr, de, es only; others fail as `unsupported_language`. The remote id is `lang:word`. Authorization is the whole secret.
- Write safety: everything before the final write call is a read or idempotent, so its failures are ordinary plugin errors and mean "nothing written" (Retry). From the moment the write request is sent, a dropped connection, timeout, 5xx or unreadable answer is returned as `unknown` and the row becomes Uncertain. The host adds the same rule for a host-side timeout, a dead plugin host and a cancel during an upsert. 429 is a retry (with Retry-After), 401/403/402 are Failed.
- Worker per target: first settle Uncertain rows (lookup: found gives Succeeded and no write; absent gives one back-fill write; the lookup cannot be answered gives the row stays Uncertain and the pass ends); then drain due rows. A target without lookup keeps Uncertain for manual check (`Resolve` delivered=true or resend with the same operationId). Retry: RetryWait with Retry-After or 30 s doubling to 1 h, six attempts, then Failed. Network, rate limit, auth and quota end the pass for that target so the remaining rows are not spent one by one. Targets run concurrently and independently; a target that throws or hangs does not block the other. No remote delete exists in the port.
- Both packages declare lookup in `VocabCatalog`, not in the manifest (the manifest parser has no such key; ARCHITECTURE 8.3 says the manifest declares it).

Evidence: full suite 1614 total, 1612 pass, 0 fail, 2 skipped (machine-dependent audio); +35 tests. Covered: DATA05 remote half (two targets independent, one offline or auth-failing or throwing; unfavorite cancels unsent rows and never calls the remote), DATA06 (lost answer then restart finds the note, one `addNote`; crash before the write landed is back-filled once; no-lookup target stays Uncertain and is never resent), duplicate detect, vendor errors, auth failures (key never in the error), offline, 429, host timeout, backoff and attempt limit on a manual clock, CFG02 plugin parts (deck and word-list options, wrong field rejected, no key leak).
Not executed: real Anki (not installed here), real Eudic (no account), so the AnkiConnect and Eudic request/answer shapes follow the public descriptions and the fakes, not a live service; Eudic's accepted language list and the 404-for-absent lookup are assumptions to check against the real API. CFG02 page behaviour (stale revision not written back, 10 s / 200 items / 5 min cache) is the existing F07.2 host logic and is not re-tested here.

Open items for F15.4: create targets and instances (config, secret binding, grants), start the worker in the host and call `RunAllAsync` after a favorite, show Uncertain/Failed rows with `Resolve`, and decide where a user approves a non-default local AnkiConnect origin (today `PluginVocabTarget` approves the configured loopback origin of a Local package at call time). An auth or quota failure leaves the other rows of that target Pending but marks the current row Failed; F15.4 should offer "retry failed" (`Resolve` delivered=false).

Behaviour and decisions:
- Star: shown only on a dictionary card with an entry; the page sends the card id, the host builds the saved content (source, phonetics, meanings, examples) from the entry it shows and uses the snapshot's source language. The page asks the state when the shown word changes. No usable target: the favorite is local and the tooltip says so; unfavorite is local and the tooltip and the page say words already in Anki/Eudic are not deleted. A host without the service (or a page without a bridge) leaves the star greyed.
- Targets are enabled, keyed and configured in the existing service rows of the vocab page (toggle, key with the address confirmation, deck / word list through `Settings.LoadOptions`); the new block adds state, counts, last error, sync now, retry failed and "sync existing favorites" (favorites that predate a target are not queued by enabling it; the button queues the missing rows only). The AnkiConnect optional key can now be saved (`BuiltInCatalog` lists `apiKey` for it) and counts only when "use an API key" is on. Eudic is usable with its key saved and granted.
- Field mapping: there is no free mapping. The page offers the one export-content choice of PLAN 6.6 (definitions, phonetics, examples), format and deck name; the Anki sync note type keeps its fixed fields (F15.3). Export choices are not persisted in settings.yaml (page-local per export).
- Export: save dialog (port), exporter on a worker thread, result with path or error code, Skipped and cleaning notes in the page. Cancelled dialog changes nothing. One export at a time.
- Local origin approval (F15.3 open issue 3), decided: the F07 grant pattern covers secrets only and has no prompt for local origins. The user's act of typing the AnkiConnect address on this page is the approval, limited to loopback addresses (127.0.0.0/8, ::1, localhost). Any other address makes the target unusable (`vocab.reason.originNotLocal`) and nothing is queued or sent. The sync call and, new in F15.4, the options call both approve the loopback origin; before this the deck list for a loopback AnkiConnect was refused by the broker (the F15.3 tests approved it themselves).
- Options call for a vocabulary package returns `missing-credential` when its key is needed and not saved/granted (instead of calling the vendor).
- Last error codes are the last failure kind per target from the worker (`VocabSyncReport.LastError`), kept in memory until a pass delivers something; they are not persisted across restarts. The page does not show vendor text or exception messages, only the error class.
- Sync loop on a manual clock: a row waiting for its backoff is retried by the next poll with no user action; `Stop` cancels a call in flight and its row becomes Uncertain (never resent blindly).
- The "settings" event is pushed to the Settings window after a favorite, a resolve or a finished pass.

Evidence: full suite 1643 total, 1641 pass, 0 fail, 2 skipped (machine-dependent audio); vitest 193 (18 files), vue-tsc clean. Rows: CFG02 UI part (state and reasons, options only for a usable instance, no secret in the view), DATA05 UI part (local favorite without target, per-target queue, unfavorite never calls a target), DATA06 UI part (Uncertain listed and resolved as delivered or not delivered with the same operationId, retry failed), DATA07/DATA08 UI part (export through the dialog port, path or error, only-new, content columns).
Not executed: a real save dialog (`Win32VocabSavePicker` compiles only), real Anki/Eudic sync and imports, the page in the packaged WebView on a desktop, NativeAOT publish with the new code (not published per CLAUDE.md; the new host code uses `Utf8JsonWriter` and source-generated JSON only).
Open: (1) the options call's host-side credential check covers key/grant only; a Retry-After/rate-limit answer from the vendor shows as an empty list with the error class, as for the other packages. (2) Last error codes and export choices are not persisted. (3) `Vocab.Collect` asks the state once per shown word, so a favorite made in another window shows after the next result; a "favorites" event could remove that. (4) The user's favorites are not listed anywhere (by design: no vocabulary management window); only export reads them.
