## F12.1 scope and contracts

- Ports in `src/Susu.Abstractions/AudioCapturePorts.cs`: `IAudioCapture` (`HasDevice`, `StartAsync`), `IRecordingSession` (pause/resume, `StopAsync`, `Cancel`, level and phase events, `Completion`), `IMicrophoneDevices`/`IMicrophoneStream` (thin device layer, 16-bit mono PCM), `RecordingResult` (status, `RecordedAudio` WAV lease, `Reason`, `ErrorCode`).
- Recorder in `src/Susu.Jobs/AudioRecording.cs` (`AudioCaptureCoordinator`, `RecordingSession`): one recording at a time (`mic.busy`), samples streamed into a WAV file lease, sleep = no chunk for 3 s, error codes `record.diskFull` / `record.writeFailed` / `mic.failed`.
- WASAPI in `src/Susu.Windows/Audio/WasapiMicrophone.cs`: default console capture endpoint, shared mode, 16 kHz mono via `AUTOCONVERTPCM`, one MTA thread, default-device check every 250 ms, reuses `Com.cs`.
- Wiring: `ShellCoordinator.AudioCapture` set in `src/Susu.Host/Program.cs`. No entry point reaches it; the Voice entry stays InDevelopment until F12.3.
- Bug found while testing: a channel completed with an exception surfaces as `ChannelClosedException` with the real error as inner exception; the reader now rethrows the `MicrophoneException` (otherwise every device loss would have read as plain removal).
- Tests: `dotnet test --project tests/Susu.Tests.Unit -c Release --no-restore --filter-class "*AudioRecordingTests"` (18 tests: 17 pass, 1 skipped for no microphone). Full suite 1249 total, 1248 pass, 1 skipped.
