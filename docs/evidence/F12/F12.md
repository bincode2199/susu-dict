## F12.1 scope and contracts

- Ports in `src/Susu.Abstractions/AudioCapturePorts.cs`: `IAudioCapture` (`HasDevice`, `StartAsync`), `IRecordingSession` (pause/resume, `StopAsync`, `Cancel`, level and phase events, `Completion`), `IMicrophoneDevices`/`IMicrophoneStream` (thin device layer, 16-bit mono PCM), `RecordingResult` (status, `RecordedAudio` WAV lease, `Reason`, `ErrorCode`).
- Recorder in `src/Susu.Jobs/AudioRecording.cs` (`AudioCaptureCoordinator`, `RecordingSession`): one recording at a time (`mic.busy`), samples streamed into a WAV file lease, sleep = no chunk for 3 s, error codes `record.diskFull` / `record.writeFailed` / `mic.failed`.
- WASAPI in `src/Susu.Windows/Audio/WasapiMicrophone.cs`: default console capture endpoint, shared mode, 16 kHz mono via `AUTOCONVERTPCM`, one MTA thread, default-device check every 250 ms, reuses `Com.cs`.
- Wiring: `ShellCoordinator.AudioCapture` set in `src/Susu.Host/Program.cs`. No entry point reaches it; the Voice entry stays InDevelopment until F12.3.
- Bug found while testing: a channel completed with an exception surfaces as `ChannelClosedException` with the real error as inner exception; the reader now rethrows the `MicrophoneException` (otherwise every device loss would have read as plain removal).
- Tests: `dotnet test --project tests/Susu.Tests.Unit -c Release --no-restore --filter-class "*AudioRecordingTests"` (18 tests: 17 pass, 1 skipped for no microphone). Full suite 1249 total, 1248 pass, 1 skipped.

## F12.2 scope and contracts

- **Catalog (`src/Susu.Domain/Asr.cs`, `Speech.cs`):** `SpeechModel` now carries `AsrLimits` (formats, `maxBytes`, `maxRequestBytes`, `maxSeconds`, upload kind, fixed request overhead). P-R01 (`whisper-1`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`: multipart, 24 MB file, 25 MB request, 300 s) and P-R02 (`gemini-2.5-flash`: Base64 JSON, 12 MB file, 18 MB request, 300 s) use the PLAN 4.7.2 figures. Both packages are `Installed` now, so they load as plugins; the limits live in the catalog, not yet in the manifest (the manifests carry only config; `asr.models` parsing is not added).
- **Negotiation:** `AsrEncodings.Negotiate` intersects a model's declared formats with the local encoders (WAV 16 kHz mono 16-bit PCM only). No intersection, or less than one second fitting the limits, means `SpeechCatalog.Check` returns `format` and the model is not selectable (`Encodable`). AAC is never produced. The vendor and host limits (32 MiB binary, 48 MiB Base64 JSON) apply, the lower wins.
- **Pipeline (`src/Susu.Jobs/AsrPipeline.cs`):** `AsrTranscriber` reads the WAV, measures 20 ms frame RMS with an adaptive threshold (3 × the 10th-percentile frame, clamped 150..500), and `AsrChunkPlanner` plans chunks: at most the largest sample count for which file size, estimated whole request and duration all fit, cut at the latest silence of at least 400 ms in the second half of the window, else hard at the limit. Silence at chunk edges is trimmed (200 ms pad kept) and an all-silent window is not sent; positions stay absolute so pauses keep their place and offsets only grow. Each chunk is written as a WAV lease, measured again (actual file, estimated request), sent by handle one at a time, and its lease released when the call ends. A chunk failure fails the run with no partial text.
- **Merge and validation:** text joins in chunk order (no space next to CJK). `PluginAsrProvider.Parse` reads the raw JSON strictly (missing or non-finite start/end, missing text, wrong kind, not an array: `bad_response`), then `ValidateSegments` against the chunk length rounded up to 10 ms (vendors report two decimals). `AsrTimeline.Append` adds the chunk offset and refuses a segment that would start before an earlier one. An empty segment list or empty text is a chunk without speech; all chunks empty is `NoSpeech`.
- **Request cap (`Broker`/`NetworkBroker`):** the call grant carries `MaxRequestBytes` (`HostSession.Invoke(..., maxRequestBytes)`), and the network broker measures the real body (multipart length or JSON bytes) and returns `bad_response` before sending when it is over. The plugin cannot change it.
- **Finding:** `JsonNode.ToJsonString()` escapes `+` as `+`, which made a Base64 JSON body about 8 % larger than its Base64 length and broke the size estimate. A body that carries Base64 files is now written with relaxed escaping (`NetworkBroker.Base64JsonOptions`); this also shrinks Tencent OCR uploads. Not run under NativeAOT (no publish): `JsonNode.ToJsonString(options)` with an encoder-only options object is expected to be AOT-safe but is unverified.
- **Contracts:** `AsrRequest { audio: FileHandleInfo, model, output, lang? }` replaces the hand-written `asr?(req: { audio: string; ... })` line in the generated plugin d.ts (`ContractsGen --check` passes).
- **Job (`src/Susu.Jobs/AsrJob.cs`, `src/Susu.Abstractions/AsrPorts.cs`):** `AsrJob.TranscribeAsync(RecordedAudio, lang, output)` takes the recorder's WAV lease, owns it until the job ends, handles Unavailable/NoSpeech (also the recorder's `Silent` flag: no request)/Failed/Cancelled, supersedes a running job, and hands text to the same translate callback as `OcrJob` when auto-translate is on. `PluginAsrProviders.Create(settings, slot, ...)` builds the provider from the Asr or VideoAsr selection (none when the model is unknown, text-only under video, has no local format, or lacks a saved and granted key). It is not wired into `Program.cs`: the Voice entry and settings are F12.3.
- **Plugins:** `src/Susu.Host/plugins/openai-asr` (multipart `file` part from the handle, `Authorization: Bearer`, `json` or `verbose_json`) and `gemini-asr` (`inlineData` filled by `bodyFiles` at `/contents/0/parts/1/inlineData/data`, `X-Goog-Api-Key`, refusal/truncation/empty output = `bad_response`). Both `check` ok with `Susu.PluginCli`.
- **Tests:** `dotnet test --project tests/Susu.Tests.Unit -c Release --no-restore --filter-class "*AsrPipelineTests"` (37, fake provider) and `--filter-class "*AsrPluginTests"` (27, real sandbox against a loopback vendor; needs the published `susu.exe`, takes the plugin folders from the source tree). Existing `SpeechSettingsTests` expectations moved from `not-installed` to `missing-credential`. Full suite 1313 total, 1307 pass, 6 skipped.

## Open issues

- Real microphone run (REC01 normal/denied, REC02, REC03 with a real unplug and sleep) needs a physical machine.
- The real WASAPI default-change and invalidation classification is code-reviewed only; no device to exercise it.
- F12.2 against real vendors (A01) is not run: no OpenAI or Gemini account. `whisper-1` timecode precision (P95 ≤ 1 s) and the 10 ms end-time tolerance are untested against the real API.
- F12.2 limits are in the catalog, not parsed from a manifest `asr.models` block; a third-party ASR plugin cannot declare its own limits yet (not in the F12.2 exit cases).
- The VAD is energy-based (adaptive RMS threshold, fixed 400 ms / 200 ms constants); it is tested on synthetic tone/silence, not on real noisy speech.
- The 42-minute video half of A08 and the SRT exporter belong to F14.
