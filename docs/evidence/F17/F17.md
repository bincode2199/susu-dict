Decisions and behaviour:
- **File**. Plain: a zip of `manifest.json` (format 1, schema, app version, created, per-file SHA-256), `settings.yaml`, `plugins.json` (user package identities: id, version, signer, hash; no code). Encrypted: the magic `SUSUBAK` plus version byte 1, a length-prefixed JSON header (PBKDF2-SHA256, iterations, 16-byte salt, 12-byte nonce) and AES-256-GCM over the same zip with `secrets.json` added when keys are included; the header is the associated data. PBKDF2 uses 600,000 iterations on export. A plain file has an integrity check but no authenticity (anyone can rebuild it with a consistent manifest); that is why it carries no keys.
- **Keys**. Not exported by default. Including keys requires a password (8 to 256 characters) and the whole file is encrypted. A plain file with a `secrets.json` is refused on import (`secrets-unencrypted`). Imported keys are re-protected with the importing user's protector at preview time; the stage on disk holds a ready `secrets.dat` and never plaintext keys.
- **Authorization is never imported**. Grants are dropped on export and again on import, so every account must be re-authorized in the service settings; keys the backup did not bring show as not saved. A crafted settings.yaml carrying a grant for another origin ends with none (tested).
- **What a backup holds**: the settings (language, hotkeys, network, accounts without grants, instances, services, prompts, speech/OCR choices) and optionally keys. ARCHITECTURE 8.1 excludes the favorites database, so the backup holds no history, favorites, entries, outbox, logs or caches; the preview says how many favorites and open outbox rows stay untouched. The task text listed "history, favorites/entries/outbox" among things a restore would replace; the architecture and DATA09 say the DB is not imported, and this follows them (open item 1).
- **Bounds** (checked before the KDF or any entry is read): file at most 16 MiB; password at most 256 characters; KDF iterations 600,000 to 2,000,000 (outside it: `kdf-params`, no key derivation runs; a test times the refusal under 1.5 s); salt 16 to 64 bytes, nonce 12; entry count from the zip end record at most 16; only the four fixed names (anything else, including `plugins/...`, `susu.db`, caches and logs: `unexpected-entry`; separators, `..`, drive, stream or control characters: `path-escape`; duplicates refused); entry at most 8 MiB, total at most 32 MiB, expansion at most 100 times once an entry passes 1 MiB (counted while reading, so a lying header cannot get past).
- **Preview** (`Backup.Pick`, then `Backup.Unlock` for an encrypted file): verifies the whole file and writes only under `%LOCALAPPDATA%\Su-Su\import\staged`; the live `settings.yaml` and `secrets.dat` are untouched (hash-checked in tests). It reports per area current to backup counts (settings, accounts, instances, enabled services, prompts), the plugin list against what is installed (missing, built in, same, older, newer), the instances whose package is missing and will be disabled, accounts needing authorization with the keys the backup did not bring, local keys the restore removes, whether the schema is older (migrated), and the kept favorites and outbox counts. Conflict keys: `plugins-missing`, `services-disabled`, `accounts-need-authorization`, `keys-missing`, `keys-removed`.
- **Missing plugins** are disabled, not installed: every service of an instance whose package this install lacks is written `enabled: false`; the plugin list is information only and nothing is downloaded or unpacked.
- **Switch at the next start**: `Backup.Apply` (token only) marks the stage Ready. At start, after the journal recovery, `ApplyPending` verifies the staged hashes and re-parses the settings, fixes the final bytes (revision moved past the current file's) and records their hash, keeps a restore point (the old `settings.yaml` and `secrets.dat`, which stay DPAPI ciphertext) once per import, then commits both files through the existing journaled `ConfigTransaction`. A Previewed stage that was never confirmed is dropped. Any failure (tamper, invalid settings, disk full) clears the stage, leaves the old pair and records a Failed result the page shows until dismissed. An import that crashes the start three times is abandoned (`too-many-attempts`).
- **Undo**: the restore point is kept after a commit; `Backup.Undo` stages it as a Ready import of source `undo`, switched at the next start through the same path (and then its own restore point holds the config from before the undo).
- **Page**: export (keys checkbox, password, dialog), restore (dialog, password step, preview, apply, cancel), the scheduled notice, the last import result with dismiss, undo. The page never receives a path (file name only), a key or a grant. Passwords are cleared after use and when the window hides, and do not appear in any view.

Decisions and behaviour:
- **Diagnostics are allow-listed, not cleaned.** The zip holds `README.txt`, `diagnostics.json` (version, build, OS and runtime description, UI language, proxy mode and counts, each string shape-checked and checked against the registry) and the rotated logs in a reduced form (at most 4 MiB, newest lines kept). A log line is parsed; only `t`, `event` and the logger's whitelisted fields are copied. Identifier fields must look like identifiers and not like credentials; numbers stay; `url` becomes scheme and public-looking host only (no path, query, port, user-info, IP, one-label or private-suffix host); plugin `message` becomes `messageChars`; unknown fields, nested values, non-JSON, over-long lines and anything that still matches a credential shape or a registered value are dropped and counted. After the zip is built every entry is checked against the registry once more; a hit stops the export (`leak-detected`, nothing written, the entry name is kept for the developer). The write is temp file then move, so a failure leaves no partial file.
- **What the registry holds** (`SensitiveRegistry.Attach`): every saved key and the proxy password (existing ones at start, new ones through `SecretStore.ValueStored`), user name, machine name, profile folder, the Windows machine GUID, account labels the user typed (a label equal to its service id is the default and is not personal), proxy host and user name. Each value is matched raw, URL-encoded (also doubled and `+`), JSON-escaped, UTF-16, hex, and in Base64 at all three byte alignments (standard, URL-safe and URL-escaped), so a value inside a longer Base64 run is found. Raw, URL and JSON forms ignore case; Base64 and hex pieces are exact and at least 8 characters (a case-folded 6-character piece matched ordinary words in a first draft and made a legitimate export fail closed). The same test run also caught a hole in the version check (a build string such as `1.0+<machine name>` passed the shape rule), now closed by the registry check.
- **The log** (S10): `RedactingLog` applies the registry and `SensitiveText.Standard` (Authorization, Cookie, Set-Cookie and key headers, Bearer and Basic tokens, key=value secrets, JWTs, common key prefixes, URL user-info and query strings, e-mail, IPv4 and IPv6, MAC) to every string field, and `Strong` (paths, file names with media or document extensions, GUIDs, long opaque blobs) to plugin messages. Before F17.2 nothing in the host ever called `RegisterSecret`, so saved keys were not masked at all; now they are. Free text that is not a secret and not in a registered set (user text in a plugin message, for example) is only caught by shape; the log keeps plugin messages by design, the diagnostics export does not.
- **What is not promised** (S10): a server that echoes a value re-encoded in an unanticipated way (ROT13, reversed, split) is not caught in the log; `S10_arbitrary_transformations_are_outside_the_guarantee` records that. The export drops free text wholesale, so such a value does not reach the zip either, but that is a property of the export, not a claim about the log.
- **Licenses**: generated from the repository's own inventory; a license text is included only where a real file exists (QuickJS, WebView2, 23 npm packages); the NuGet rows (MIT or Apache-2.0 per package metadata) carry the SPDX id, copyright and project URL and no text because the packages ship none. The inventory names `susu_windows_probe.dll` for the WebView2 loader (an F00 name, copied as is). The .NET runtime notices come with the ILCompiler runtime package. The installer must copy `LICENSES/NOTICE.txt` next to the app (F18).
- **Data clean** (about page; each entry needs a second click and the host refuses a request without `confirm = true`): *caches* (finished sessions and unleased files in `cache/`; leased files stay and are counted as in use), *logs* (all `susu-*.jsonl`; a held file is truncated instead), *screenshots* (the kept copies in this app's own index only; a replaced or held copy stays), *favorites* (entries, deliveries and export records; this app has no separate translation history), *settings* (defaults through the journaled save; accounts, grants, instance bindings and keys are kept), *accounts* (every account, grant, binding and saved key including the proxy password, in one two-file transaction). Never touched: files outside the app data folders (a test plants user documents, a plugin package and a picture beside the kept ones), the settings file itself, the database file, installed plugin packages. Plugin key-value data and the backup restore point have no entry yet.
- **zh/en check** (`f17-i18n.test.ts`): both catalogs have the same keys, none empty, same placeholders; English holds no Chinese text; a Chinese message without Chinese text must equal the English one (API Key and similar); every literal `t('...')` key in the UI source exists in both; every dynamic prefix has entries; no template or code line outside the catalog carries Chinese text or a bare English phrase (the language's own name, 简体中文, is the one exception). Gaps found and fixed: Chinese punctuation hard-coded in code (the enumeration comma, semicolon, comma, brackets and colon in the service grant text, the speech choice note, the config-field error, the service list under the network test and the dictionary meanings) is now `sep.*` catalog entries, so the English UI shows `, `, `; ` and `(...)`.
- **Staging ACL (F17.1 open item 3)**: `PrivateFolder.Ensure` removes inheritance and grants only the current user and SYSTEM; applied to `import/` (the stage, pending record, result and restore point inherit it) and to `transactions/`. Tested with the real ACL on the temp root: protected, exactly two SIDs, children inherit. Note that `secrets.dat` itself has no special ACL (it relies on DPAPI and the roaming profile default), so the stage is now stricter than the live file (open item 1 below); the earlier wording "same ACL as secrets.dat" had no ACL to copy.
