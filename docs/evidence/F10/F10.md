## Scope and contracts

- **F10.1:**
  - **Ports and player:** `Susu.Abstractions/SpeechPorts.cs`; `SpeechPlayer` (`SpeakAsync`, `PlayAsync(acquire)`, `Stop`, `StateChanged`, `Device`, `IdleAsync`). Outcomes: Completed, Stopped, Superseded or Failed (service error, or device NoDevice/DeviceLost/Unsupported/Failed). `SpeechBackend` (`Player`, `Tts`, `DictionaryAudio`, `RequestFor`, `SpeakSelectedAsync`) is reached through `ShellCoordinator.Speech`.
  - **Result files (B07):** a call's response files are released when the call ends unless the caller passes `adoptResultFiles`; the host adopts a result before the call's leases are released.
  - **Native:** `SapiTtsProvider` speaks plain text into a leased 22.05 kHz WAV and deletes partial output on cancel or timeout. `WasapiAudioSink` decodes with Media Foundation and plays through shared-mode WASAPI. SAPI voices are served through the options broker.
  - **P-S01 Microsoft:** `Ocp-Apim-Subscription-Key`; `region` selects the endpoint and grant origin `https://{region}.tts.speech.microsoft.com` (malformed → `eastus`). Escaped SSML with prosody rate; raw MP3 comes back as a handle. 5000 characters; voices from `/cognitiveservices/voices/list`.
  - **P-S02 Google:** `X-Goog-Api-Key`; 5000 bytes. The broker decodes `/audioContent` into a file; errors come from `/error` and are classified by `error.status`.
  - **P-S03 Tencent:** TC3 for the `tts` service. Speed maps to Tencent's −2..6 scale; MP3 from `/Response/Audio`; errors from `/Response/Error`. Chinese and English only: 150 Chinese / 500 other characters. A fixed list of 7 voices.
  - **All three:** 401/403 → auth; 429 → rate_limited with Retry-After; 5xx → network. A success is played only if its bytes are audio. Speed is clamped to 0.5–2.
  - **Dictionary audio:** `DictionaryAudioFetcher` is wired (`FetchClipAsync`).
- **F10.2:**
  - **Contracts:** window kind `Speech`; commands `Speech.SpeakCard`, `Speech.Play`, `Speech.Stop`; views `SpeechStateView`, `SpeechBarView`; `CaptureTrigger.Pronounce`; UI port `Anchor`.
  - **Bar placement (PLAN 6.5, DESIGN 9):** just below the UIA selection rectangle, left-aligned, using that monitor's DPI; it flips above at the bottom edge and stays inside the work area. With no rectangle it goes to the pointer. The window never activates. It hides 5 s after playback ends (the spec doesn't define this).
  - **Features:** Pronunciation is registered Available whenever the selected TTS service can run. Every finished card has a read-aloud key (DESIGN 8 order).
  - **Phonetic keys:** they play the entry's existing dictionary audio, otherwise they speak the word. No extra lookup is ever made (TTS03). There is no "prefer dictionary audio" setting yet.
  - **Playback timeout:** 45 s, sized for the slow first SAPI synthesis.
- **F10.3:**
  - **Cache limits (ARCHITECTURE 8.4):** `TtsCache`, 32 MiB / 7 days, plus a 256-entry cap the spec doesn't define; least recently used goes first.
  - **Cache key and storage:** the key is a SHA-256 of instance, config fingerprint (package, revision, config values, bindings, credential-write counter), voice, language, speed and text; no text or secret is stored. Entries are shared file leases in the session folder, deleted on exit; a persistent cache would need an explicit user setting, which doesn't exist yet.
  - **Invalidation:** a settings change or credential write drops that service's entries. `Clear()` is the cleanup entry.
  - **Devices:** WASAPI `0x88890026` counts as DeviceLost; the bar shows `device-lost`, the lease is released and the next playback works.
  - **Cloud vs SAPI:** cloud synthesis runs off the caller's thread, so a hung vendor call or a killed plugin host never blocks SAPI (real-sandbox + real SAPI test).
  - **SAPI timings (fresh process):** COM init 7–9 ms, voice enumeration 18–557 ms, first synthesis 163–313 ms, later syntheses 80–230 ms. The earlier ~20 s didn't reproduce (likely a cold disk or antivirus scan on first load). A loaded SAPI costs ~3 MiB private and 12–15 MiB working set, so it isn't pre-warmed at startup (PER02); it warms once, off the UI thread, when Settings first lists native voices. Phase times are logged as `tts.sapi`.
  - **Dark theme:** the speech bar border uses `var(--line-accent)`.
