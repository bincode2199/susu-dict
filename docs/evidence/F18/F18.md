## F18.1 · NSIS per-user installer (2026-10-02)

Conclusion: the installer script, build pipeline and the application side of install, exit coordination and uninstall exist and are tested against real Windows APIs. **The NSIS script has never been compiled**: `makensis` is not installed here (not on PATH, not in `C:\Program Files (x86)\NSIS`, not under `.tools`), and nothing was downloaded. `winget` is present, so the user can approve `winget install NSIS.NSIS` (or a manual install); then run `tools/build-installer.ps1`. Expect small NSIS syntax fixes on the first compile.

| Piece | Where | Behaviour |
|---|---|---|
| Installer script | `tools/installer/susu.nsi` | Current user (`RequestExecutionLevel user`), `%LOCALAPPDATA%\Programs\Su-Su`, HKCU uninstall entry, Start Menu shortcut, optional "start when I sign in" (off by default), English and Simplified Chinese. WebView2 Runtime missing: message with the Microsoft page offered in the browser, exit code 3, no download. Single installer instance (mutex, exit 6). Unsigned builds say so in the installer title. |
| Running-instance coordination | `susu.exe --installer-query` and `--installer-exit` (`src/Susu.Host/InstallerMode.cs`, `src/Susu.Windows/InstallerSupport.cs`, `Shell/Dispatcher.cs`) | The installer queries the running instance through its message window: exit code 100 + n means running with n tasks in flight (recording, video job, plugin calls). The user sees the count and confirms (a silent run with tasks aborts, exit 4). `--installer-exit` asks for the same shutdown path as the tray Exit and waits until the single-instance mutex is free; a timeout is reported and nothing is killed (exit 5 in the installer). |
| Uninstall | `susu.exe --installer-uninstall [--delete-user-data]` | Removes leftover plugin-sandbox AppContainer profiles (`Susu.Plugin.Host.*`, found through the profile mapping registry), the start-at-login entry and, only with the explicit Yes (default No, also when silent), the settings, database and caches under `%APPDATA%\Su-Su` and `%LOCALAPPDATA%\Su-Su`. Kept screenshots in Pictures are never touched. A reparse point at a data folder is unlinked, not followed. Refuses while an instance runs (exit 13). A custom `--data-root` run never removes the login entry. |
| Start-at-login choice | `install-options.json` (`src/Susu.Host/InstallOptions.cs`) | The installer writes the Run entry and a one-line options file; the first start applies it through the normal settings save and deletes the file, so the app's own startup reconciliation does not undo the choice. |
| Sandbox profile lifecycle | existing `ContainerHost` and `HostSession` | Each session creates a uniquely named profile and deletes it on close; creation failure throws and no plain process is started (no `StartPlain` use outside `ContainerHost`; guarded by a test). Crash leftovers are removed by the uninstall step. |
| Process cleanup on parent death | existing native job object (`KILL_ON_JOB_CLOSE`, one process, memory limit) | Verified with a real parent process (a second test host) killed abnormally. |
| Build pipeline | `tools/build-installer.ps1` | Refuses an incomplete publish or missing `LICENSES/NOTICE.txt`; stages the publish output without `.pdb` plus `LICENSES/NOTICE.txt` and `third-party.json`; writes `staged-manifest.json` (path, size, SHA-256, `signed`); signing hook (`-SignTool` and `-SignArgs` with `{file}`, or `SUSU_SIGN_TOOL` and `SUSU_SIGN_ARGS`) signs only Su-Su's own binaries and the installer; with no hook the build is UNSIGNED (`UNSIGNED.txt`, title text, `-UNSIGNED.exe` name); `-RequireSigned` fails instead. No certificate exists and none is committed. Exit 3 when makensis is missing after staging. |

Real staging of the current publish output: 64 files, 22.4 MB, unsigned, manifest and notices included.

### Bug found and fixed

`VocabService.StopAsync` awaited its loop on the UI synchronization context, and `Program` calls it with `GetResult()` after the message loop ended. After any exit request the process stayed alive (`app.exit` never logged, mutex held). Found by the real-instance installer test; fixed with `ConfigureAwait(false)`. This also affected the tray Exit whenever the vocabulary loop was running.

### Tests (`tests/Susu.Tests.Unit/F18InstallerTests.cs`, 14 tests)

Staging and manifest (hashes, no `.pdb`, notices); incomplete publish refused; signing hook and `-RequireSigned`; static rules of the `.nsi` (user level, no download plugin, data question default No and only on the Yes path); uninstall keep versus delete with a junction (scratch registry key under HKCU, never the real Run key); AppContainer profile create, list and uninstall removal; forced creation failure surfaces `ERROR_ALREADY_EXISTS` instead of a plain launch; query and exit protocol with a real message window and in-flight count; a non-exiting instance reported as timed out and not killed; the published `susu.exe` commands against a real running instance (query 100, uninstall refused 13, exit returns 0 and the process is gone); X06 parent kill with a real child; session close and a 4 MiB budget failing visibly.

### Not executed and open

- NSIS compile, a real install, upgrade over a running instance, uninstall from Apps and features, and the Run entry as written by the installer script (the script's own logic is only statically checked).
- WebView2 missing or disabled (UPD07): registry detection is in the script; not run.
- Clean Windows 11 user install (needs another user or machine).
- Memory budget: only that a 4 MiB budget fails the start visibly. A runaway allocation in a running plugin was not exercised.
- The installer query counts recording, a video job and in-flight plugin calls; other work is not counted.
- The installer's instance name assumes the default data root.
