## F14.1 · File pick, token, Media Foundation probe and decode

- Status: **done** (2026-10-01), pending the module's independent verification.
- Code: ports `src/Susu.Abstractions/MediaPorts.cs` (`IMediaDecoder`, `IMediaAudioReader`, `IMediaTokens`, `IMediaPicker`, error codes `MediaErrors`); `src/Susu.Jobs/MediaSlicer.cs` (token table `MediaTokens`, `MediaSlicer`, `MediaSession`, `MediaSlice`); `src/Susu.Windows/Media/MediaFoundationDecoder.cs` (real MF, explicit vtable calls) and `Win32MediaPicker.cs` (common file dialog). Tests: `tests/Susu.Tests.Unit/MediaDecodeTests.cs` (class filter `*MediaDecodeTests`), `MediaFixtureWriter.cs` (test-only MF sink writer).
- Not built here (F14.2/F14.4): the video job, UI, drag-in wiring (the drop handler calls `IMediaTokens.Issue(path)`), host wiring in `Program.cs`.

| Piece | How it works |
|---|---|
| mediaToken | `IMediaTokens.Issue(path)` returns an opaque random token only for an existing file; the picker and a future drop handler both end there. Only host decode code calls `TryResolve`; the UI gets the token and `DisplayName` (file name, no directory). |
| Probe | `ProbeAsync` lists duration, video present, and every audio stream (codec, rate, channels, decodable). A stream is decodable when MF can produce 16 kHz mono 16-bit PCM from it. No-audio and no-decodable-audio are reported in the probe, not thrown, so the UI can explain before upload. |
| Stream choice | First decodable audio stream (video streams deselected). |
| Decode | MF source reader converts to 16 kHz mono PCM itself (no own resampler). One MTA thread owns the COM objects of a file. Blocks carry the container timestamp. |
| Slices | `MediaSession` cuts the PCM into WAV leases (default 5 minutes each; the ASR chunk planner then splits inside a slice by model limits). A timestamp gap above 200 ms is filled with silence so slice start times stay on the container time axis. |
| Back-pressure | A semaphore of 2 permits: a slice holds its permit until the consumer disposes it (after the ASR upload). Decode never creates a third slice; memory is one slice buffer (9.6 MB) plus two files. |
| Cancel | `Dispose` or the token stops decode, closes the source file, deletes every undisposed slice (handed-out ones too). |
| Disk full | A write failing with ERROR_DISK_FULL (0x70) or ERROR_HANDLE_DISK_FULL (0x27) deletes the torn file and yields `Failure(media.diskFull, Retryable)`. `Retry()` re-writes the same slice from the PCM already decoded (nothing decoded twice, no corruption). Other write errors end the session as `media.writeFailed`. |
| Exit codes | `media.unknownToken`, `media.notFound`, `media.unsupportedEncoding`, `media.noAudio`, `media.corrupt`, `media.openFailed`, `media.diskFull`, `media.writeFailed`. A container MF does not recognize is `unsupportedEncoding` (MF cannot tell unsupported from badly damaged); a read failure midway is `corrupt` and earlier slices stay valid. |

## F14.2 · Video job

- Status: **done with fakes and one sandbox run** (2026-10-01), pending the module's independent verification. The real ASR vendor and real translation services were **not executed** (no accounts).
- Code: ports `src/Susu.Abstractions/VideoPorts.cs` (`ISubtitleTranslationProvider`, `IVideoUploadConfirmation`, `VideoUploadNotice`, `VideoCue`, `VideoJobState`, `VideoErrors`); `src/Susu.Jobs/VideoJob.cs` (`VideoJob`, `VideoJobs` service, `VideoResultStore`, `SingleItemSubtitleProvider`). Wiring (minimum): `ShellCoordinator.VideoJobs` (`Shell.cs`), built in `Program.cs` and cancelled at exit. Tests: `tests/Susu.Tests.Unit/VideoJobTests.cs` (33, filter `*VideoJobTests`) and `VideoJobSandboxTests.cs` (1, real OpenAI package in the sandbox against the loopback vendor; it needs the published `susu.exe`). Step 0 (separate commit): the recording and F13 memory/handle tests moved into the non-parallel `MediaDecode` collection; the full suite passed twice in a row (1471 total, 1464 pass, 7 skipped).

| Piece | How it works |
|---|---|
| Services | `VideoJobs.Start(token, from, to)` asks its two factories for the video ASR and the translation service at that moment. Refusals before any media work: `video.noAsr`, `asr.noTimecodes` (A03, no fake times), `video.noTranslation`, `video.busy` (one job at a time). `VideoJob` itself also fails `asr.noTimecodes` before opening the file. |
| Upload gate (T06) | After probe the job publishes `AwaitingConfirm` and calls `IVideoUploadConfirmation` with a `VideoUploadNotice`: file name (no directory), duration, ASR service and model, upload size upper bound (32,000 bytes per second), chunk seconds and bytes limit, translation service name and its limits, a provider-supplied quota note key (MyMemory: `video.quota.sharedDaily`). `EstimatedCharacters` and `EstimatedPrice` are always null (not known before ASR, never made up). No port, a no, or cancel ends in `Cancelled` with `video.notConfirmed` and no request. Slices are already being decoded to local temp files during the wait (at most two, no network); cancel deletes them. |
| ASR per slice | Each slice goes through the F12.2 `AsrTranscriber` with `segments`; segments are moved by the slice start onto the media time axis with `AsrTimeline.Append` (a result that would go backwards fails the job, none of that slice enters the list). A silent slice makes no request. A slice that succeeded is never sent again. |
| Cues and translation | Cues get stable ids (`c1`, `c2`, ...), original text trimmed. Translation uses `SubtitleMapper`: long cues split into parts by the service limit and merged by part index (time unchanged, T05); batches by the soft cap (20 items, 1500 scalars, service hard limits); replies matched by id only (T03). A malformed batch (missing, duplicate, extra id, null or blank text) is discarded and its parts are asked once each alone; a single that is still malformed marks that cue `TranslationError` and the job goes on (T04). A transient network, timeout or busy answer gets one more try. Any other failure ends the job `Failed`. |
| Incremental list | Events `CueChanged(cue)` (added, translated or failed, same id) and `StateChanged(state)`; translation of a slice's cues starts as soon as its ASR is done, so the list fills in order. |
| Quota (T07) | `quota` or `rate_limited` from ASR or translation parks the job in `QuotaExhausted` (`Quota` says which side); the old service gets no new request. `SwitchTranslator` / `SwitchAsr` (refused for a model without timecodes) then `Resume` continue: the same held slice is retried, or only cues with no translation and no error are sent. Resume without a switch retries the same service. Half-translated parts are dropped on a translator switch (another service splits differently). |
| Pause, cancel | `Pause` takes effect before the next request (the one in flight finishes), `Resume` continues; a disk-full from the slicer parks as `Paused` with `media.diskFull` and `Resume` calls `Retry()`. `Cancel` (or `CancelActive` at window close or exit) cancels the call in flight and decode; the held slice and session are disposed (no lease, no temp file, no grant). Cues made so far stay readable. |
| Results | `VideoResultStore` (in memory, 8 jobs, oldest finished goes first) keeps the job after the window closes: `Get(jobId)` returns state and cues (original and translation) for reopen and export (F14.3). Nothing survives a restart. |
| Translation adapter | `SingleItemSubtitleProvider` wraps a plain `ITranslationProvider` as one part per request (Single mode). The plugin API has `translateBatch` types but no host provider uses them yet, so no items-mode plugin exists; the items path is tested with a fake. |

### Open issues (F14.2)

- No video translation selection exists in settings: the wiring uses the first enabled translation service, one text per request. "Own translation service independent of the main window" needs a settings field and UI (F14.4); `VideoJobs` already takes any factory.
- ASR resume is per slice. A slice with several upload chunks (only when a model limit is below the 5-minute slice) re-sends that slice's chunks when a later chunk hits quota, because `AsrTranscriber` returns no partial result. With the shipped models one slice is one chunk.
- A non-quota failure (auth, network after one retry, unavailable) ends the job as `Failed`; there is no resume from it. Cues stay in the store for export.
- Slice decode starts before the confirmation (local temp files only, at most two slices); cancel removes them.
- The cue list is not validated against the media duration (the ASR provider validates against the chunk length).
- Items-mode translation through a real plugin (`translateBatch`) is not wired.

### Handoff to F14.3 and F14.4

- Export reads `VideoResultStore.Get(jobId)` (`VideoJobResult`: `State`, `Cues` with `Original`, `Translation`, `TranslationError`, `Start`, `End` in seconds); the store is `ShellCoordinator.VideoJobs.Results`. Cues with a null translation export their original, or are left out of translation-only formats, as F14.3 decides.
- The UI sets `VideoJobs.Confirmation`, subscribes via `VideoJobs.JobStarted` to `StateChanged` and `CueChanged`, and calls `Pause`, `Resume`, `Cancel`, `SwitchTranslator`, `SwitchAsr` on the job. Phases: Probing, AwaitingConfirm, Running, Paused, QuotaExhausted, Done, Failed, Cancelled; `ErrorCode` is a media code, `video.*`, or `asr.noTimecodes`; `Error` holds the provider error kind.

- Not built: UI (F14.4), host wiring of `SubtitleExporter` and `Win32SubtitleSavePicker` in `Program.cs` (the UI constructs `new SubtitleExporter(shell.VideoJobs.Results, picker)`).

| Rule | Decision |
|---|---|
| Modes | Original, Translation, BilingualOriginalFirst, BilingualTranslationFirst (DESIGN names no export spec; both orders offered). Formats SRT, VTT, TXT. |
| Bad cue | Reported (`SubtitleIssue(cueId, code)`) and **excluded**; the file is still written from the good cues. If none is left: `export.nothingToExport`, no file. Codes: NaN/infinity/negative (`time.invalid`), end <= start also after rounding to ms (`time.range`), past duration + 1 s or above 1,000,000 s (`time.outOfRange`), starts before an earlier accepted cue (`time.outOfOrder`, never re-sorted), duplicate id, empty text. Times are never repaired, moved or split evenly. |
| Overlap | Legitimate overlap and contained cues are written as given and counted in `Overlaps`. |
| Missing translation | Translation-only: the cue is left out and reported `translation.missing` (the original is not substituted). Bilingual: the cue shows its original only, no issue. |
| Timestamps | SRT `hh:mm:ss,mmm`, VTT and TXT `hh:mm:ss.mmm`; hours never wrap (100 h prints `100:`); milliseconds round half away from zero. SRT numbers are contiguous over exported cues. |
| Encoding | UTF-8 **without BOM**, LF line ends (the spec names none; a BOM is not required by any target listed). |
| Text | Any line ending becomes LF; blank lines inside a cue are dropped (they would end the cue); control characters and BOM removed; lone surrogate becomes U+FFFD. VTT escapes `& < >` (so `-->` can not occur). SRT inserts a zero-width space into `-->` in text (visible text unchanged). TXT: `[time] first line` with continuation lines indented. |
| File name | Suggested `<stem>.<original/translation/bilingual/bilingual-translation-first>.<ext>`: directory and extension dropped, invalid and control characters become `_`, Windows reserved names get a `_` prefix, trailing dots and spaces trimmed, 80 characters at most without splitting a surrogate pair, empty becomes `subtitles`. |
| Write | Flushed sibling temp file, then `File.Move(overwrite)`. ERROR_DISK_FULL / HANDLE_DISK_FULL: `export.diskFull`, `Retryable`; other IO errors `export.writeFailed`; bad or missing folder, directory target: `export.pathInvalid`. No partial file or temp is left, an existing target is untouched, retry works. (Storage's `AtomicFile` is not used: Jobs does not reference Susu.Storage, and its `.prev` backup is wrong for user files.) |
| Closed window | The exporter reads `VideoResultStore`, which `CancelActive` leaves alone; export after close does no ASR, translation or upload. After a restart (or `Remove`) the job is `export.unknownJob`. |
