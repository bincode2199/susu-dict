## Scope and contracts

| Sub-task | Delivered (code) |
|---|---|
| F02.1 | `Susu.Domain/Settings.cs` holds the settings model and first-run defaults for 21 built-in packages plus the ELS/SAPI native providers. MyMemory is the only enabled translate service and is first in `translationOrder`. `Susu.Storage/Yaml.cs` reads the strict YAML subset: anchors, aliases, merge keys, explicit tags, multiple documents and duplicate keys are rejected with path, line and column. `SettingsYaml.cs` binds schema v1 strictly (unknown fields, types, ranges, hotkey format and conflicts, cross-references) and migrates forward only (schema 0 → 1 sample); a newer schema is refused. It writes the file in a fixed key order with zh/en comments regenerated on every save. `SettingsStore.cs` checks revision and file hash on save, round-trip validates, writes a flushed temp file and replaces atomically (keeping `.prev`), and reloads hand edits after a 300 ms debounce. An invalid file keeps the last valid settings and is never replaced by defaults; a later UI save copies it to `settings.invalid-<time>.yaml` first. `Files.cs` has `ConfigTransaction`, the two-file journal (Prepared → replace → Committed; startup recovery rolls back Prepared and cleans up Committed). |
| F02.2 | `SecretStore.cs` stores each value as its own DPAPI (CurrentUser) blob. Names can be read without decrypting, and plaintext is released only by `TryRead` for the network layer. The UI-facing API is write, replace, delete and presence only. The proxy password goes through the same path (account `proxy`). `Susu.Domain/Credentials.cs` provides exact-origin normalization (IDN, IPv6, explicit port; no userinfo, path, query or wildcard), `CredentialGrant` (package + signer + secret + origin + use) and `CredentialAuthorizer`: an explicit instance binding plus an exact grant is required, and declared changes become pending confirmations. `Susu.Net/Credentials.cs` holds `CredentialInjector`, which only fills the separate `credentials` control field into reserved header, query or JSON targets. It refuses routing and transport headers and CR/LF, and escapes through one query encoder and one JSON serializer. `Susu.Windows/DpapiProtector` implements `ISecretProtector`. |
| F02.3 | `Database.cs` runs one writer thread over a bounded queue; each write is a short transaction that rolls back on any exception. Readers use their own WAL connections. Settings are WAL, `foreign_keys=ON`, busy_timeout 5 s, parameterized SQL only. Forward migrations take an online backup first (`susu.db.v<N>.bak`). A newer database is refused with a pointer to the compatible backup, and `RestoreBackup` restores it. `BackupToAsync` uses the SQLite backup API. Schema v1 has `meta`, `window_state`, `usage` + `usage_events` (deduplicated per attempt and metric, events purged after 7 days), `plugin_installations` and `plugin_kv` (host-bound namespace; quotas 1 MiB per installation and 32 MiB total; FK cascade). Vocabulary tables are reserved for migration 2 in F15. |
| F02.4 | `Leases.cs`: unguessable lease ids, reference counts, delete on last release, per-session cache folder removed on exit, stale sessions of dead processes removed at startup, nothing outside `cache/` touched. `Logging.cs`: JSONL with a field whitelist; URL queries stripped; registered secrets masked in raw, URL-encoded and Base64 forms; plugin messages capped at 4 KiB and 20/s per plugin with a dropped counter; 7-day and 10 MiB retention. `AppPaths` takes `--data-root`/`SUSU_DATA_ROOT`, and development builds default to a separate `Su-Su-Dev` folder, so tests never touch the real profile. |

Ports added to `Susu.Abstractions/StoragePorts.cs`: `ISecretProtector`, `IFaultPoint` (test-only fault injection), `ISettingsStore`, `ISecretStore`, `IWindowStateStore`, `IPluginKv`, and the settings state and save result records.

Not included: settings export/import (`.susubak`), which is F17; the network transport, signers and redirect policy, which are F05; vocabulary tables, which are F15; the settings UI, which is F03 and F07.

## Handoff

- F03 consumes `SettingsStore`, `SecretStore` (write-only commands from the Settings window), `WindowStateRepository` and `AppPaths`.
- F04/F05 consume `CredentialAuthorizer`, `CredentialInjector`, `PluginKvRepository`, `FileLeases` and `RedactingLog`.
- Known limitations: the transactions folder inherits the user-profile ACL; no additional ACL is applied. `usage` has no account dimension yet (`account` is empty) until F07 binds accounts to calls.
