# Windows 虚拟机安装部署计划

初版日期：2026-09-19（America/Toronto）。版本：V5（故障路径复审）。状态：已于 2026-09-21 按方案实施，实际证据和差异见 [部署记录](WINDOWS-VM-DEPLOYMENT.md)。范围：在宿主机上部署两台可供多项目复用的 Windows 11 虚拟机，首个使用项目为 susu-dict。第 2 节保留实施前的只读调查快照，不代表当前状态。

本计划到 Windows 系统和基础设备验收为止。GitHub、CI/CD、代码仓库接入、开发工具链和项目测试将在后续开发环境搭建阶段另行设计与实施，不是本次部署的前置条件或完成条件。

## 1. 决策

采用 Debian 宿主机上的 **QEMU/KVM + OVMF UEFI + swtpm TPM 2.0**，先建两台项目无关的 Windows 11 x64 虚拟机：开发机与干净验收机。每台虚拟机所有专属文件都放进 `/data/vm/<虚拟机名>/`。为严格控制固件变量、TPM、运行状态等路径，首期直接用 QEMU 启动脚本管理，不引入 libvirt 的默认状态目录。

交付两台已安装 Windows、基础驱动和系统更新的虚拟机，以及启动/关闭方法、配置清单、关键数据保存和系统重建说明。名称和基础配置不绑定具体项目。

## 3. 虚拟机与资源

| 名称 / 目录 | vCPU | 内存 | qcow2 虚拟容量 | 用途 |
|---|---:|---:|---:|---|
| `win11-dev` / `/data/vm/win11-dev` | 8（单 socket） | 16 GiB | 120 GiB | 预留为多项目开发使用；本次仅部署基础系统 |
| `win11-clean` / `/data/vm/win11-clean` | 4（单 socket） | 8 GiB | 80 GiB | 预留为多项目干净验收使用；本次仅部署基础系统 |

默认只开开发机，验收时按需启动 clean。两台合计 24 GiB；按当前 available 34 GiB 估算，约剩 10 GiB，须计入 QEMU 开销和宿主负载变化。启动后预计 available 必须至少保留 8 GiB，否则顺序运行；发生持续换页或 OOM 风险时停止新增任务。1 GiB swap 不计为虚拟机可分配内存。性能测量只开一台，暂停竞争任务。

两块 qcow2 磁盘的来宾可用容量上限合计 **200 GiB（120 + 80）**，按实际写入增长，不预分配全部容量。首期另计安装介质、安装临时文件、日志与 qcow2 元数据共 40 GiB，关键数据导出共 10 GiB，工作预算约 **250 GiB**；宿主另保留至少 50 GiB 可用空间，即初期准备约 **300 GiB 可用空间**。这不是立即占用量，也不包含完整磁盘备份或长期快照。

不做完整备份，不维护黄金镜像、磁盘副本或常驻快照链；故障通过重装与配置恢复解决。不额外安排本地代码定时备份；未来代码由项目版本管理流程保存，本次不配置该流程。

P0/P1 还要单独检查宿主系统盘及软件包缓存所在文件系统：系统软件不安装在 /data，不能用数据盘余量替代系统盘余量；根据安装事务估算下载/解包空间并保留至少 10 GiB 系统盘余量。本轮只读复核系统盘约空闲 318 GiB，属于当前观察值。

启动和安装更新前检查宿主和 guest 各自的剩余空间。宿主不足 50 GiB，或 guest 系统盘不足 20 GiB 时，先清理可再生成的缓存/旧产物；持续不足再按实际项目需求扩盘并调整预算。添加新项目不自动新增虚拟机或扩大磁盘。删除 guest 文件不保证宿主 qcow2 文件立即缩小，实际占用与回收效果需单独核对。

Windows 选仍受支持的正式 Windows 11 Pro x64 版本，实施当天依 [S2] 锁定 release/build、语言、补丁与 ISO SHA-256；不用 Insider，不绕过 CPU/TPM/Secure Boot 检查。Pro 用于可选 RDP；许可、初始联网/账户要求按官方渠道核对 [S3]，本计划不假设已有授权。

## 4. 严格目录布局与虚拟化参数

每台独立使用下列结构，不跨虚拟机共享 backing file，不链接到目录外的数据文件。创建时设目录权限 0700、敏感状态文件 0600，并使用 umask 077；固件 CODE 设只读：

```text
/data/vm/win11-dev/          # clean 采用同样结构
  config/                       # 通用启动/重建脚本、配置、版本与校验和清单
  disks/system.qcow2
  firmware/OVMF_CODE.fd          # 从发行版复制的只读固件，与 VARS 匹配
  firmware/OVMF_VARS.fd          # 此 VM 独占、可写
  tpm/                          # swtpm 持久状态
  iso/                          # 官方 Windows、签名版 VirtIO 驱动介质
  run/                          # QMP、SPICE、swtpm socket、PID、互斥锁
  transfer/                     # 临时小容量 FAT 数据交换镜像，不是系统备份
  tmp/                          # 启动程序专属临时文件
  logs/
  backups/critical/             # 小体积关键数据导出；不含系统盘/整机镜像
  evidence/                     # 系统版本、设备、启动及重建验收记录
```

宿主发行版程序/库仍安装在系统标准目录，这是虚拟化工具，不是 VM 安装数据。VM 专属工作目录及各组件支持的临时/缓存/状态路径通过显式参数指向该 VM 内部；不改写用户 HOME。持久文件、日志、崩溃转储不得落在默认用户目录、`/var/lib/libvirt` 或 `/tmp`。禁用 QEMU guest-memory core dump、宿主进程 core dump 和未指定路径的 save-state；不用 `-snapshot` 隐式临时盘。系统通用审计日志不作为可还原虚拟机状态。运行后检查进程打开的文件与 socket，确认没有 VM 专属可写文件越界。

启动配置契约（待装包后按本机 `--help` 和固件文件实际名称生成脚本，不提供猜测的可执行安装命令）：

- 显式 `-accel kvm`，失败即停止，不自动降级软件模拟；CPU `host`，固定版本化 Q35 machine type，单 socket 与上表核数。
- 使用配套布局的 OVMF CODE/VARS，CODE 只读、VARS 独占；选择带 Microsoft 密钥的 Secure Boot 固件模板，正确启用 SMM，最终以 guest `Confirm-SecureBootUEFI` 为准。只选了 UEFI 不代表已启用 Secure Boot。
- 每台独立 swtpm，TPM 2.0、独立状态目录和 socket；通过 QEMU `tpmdev emulator` 与 `tpm-tis` 接入 [S4]。TPM 不直通宿主物理 TPM。
- 主磁盘 VirtIO，安装器加载匹配架构且签名有效的存储/网卡驱动；保留驱动 ISO。必要时先 SATA 安装、装好驱动后关机切换并重验。驱动由 VirtIO 项目指向的正式渠道获取 [S5]。
- 首期标准虚拟显示设备、软件渲染；不依赖 GPU 直通。优先通过仅本机可访问的 SPICE UNIX socket 操作；若客户端要求 TCP，只监听 127.0.0.1。音频后端与输入设备按已安装版本列出的能力配置并做播放/采集实测。
- QEMU 用户态 NAT 出网，不新增宿主路由/桥接。RDP 后续已启用：QEMU 在 `127.0.0.1:13488/13489` 转发至对应 VM 的 3389，LAN 转发进程在 `192.168.1.31:13488/13489` 监听并仅允许 `192.168.1.0/24` 来源。不在其他宿主地址监听。
- 默认不挂载宿主工作区，不共享个人 HOME、SSH agent、Docker socket、磁盘分区或 Tailscale 身份。默认关闭 SPICE/RDP 的自动剪贴板同步，后续按使用需要调整。
- PID/锁防止两个 QEMU 写同一磁盘；先启动 swtpm，再 QEMU。通过 QMP 请求 ACPI 关机并等待进程退出后才停 swtpm；超时保留状态供诊断，不能自动杀进程后冒充干净关机。

NAT 只解决连接方式，不提供宿主/LAN 安全隔离。当前仅部署可信系统介质与驱动；未来不可信工作负载所需的隔离另行设计。

### 4.1 启动与生命周期的实施约束

- P0 记录 `/data` 的挂载点与文件系统 UUID；每次创建磁盘、启动或重建前，确认目标路径实际落在该文件系统上且可写。不能只检查目录存在；挂载缺失、只读或来源变化时停止，不在根文件系统同名目录下继续创建 VM。本轮真实宿主机复核为 `/dev/sdb1`、ext4、读写挂载；沙箱视图不作为宿主挂载状态依据。
- 主盘显式指定 qcow2 格式，交换盘显式指定 raw 格式；不使用不安全缓存或忽略 flush 的选项。按实际版本固定写入错误暂停、读取错误报告等策略（例如 `werror=stop,rerror=report`）。status 读取 QMP 的运行状态与块设备错误状态，区分 running、paused/I/O-error、shutdown 和进程不存在；进程存活不代表系统正常。发生空间不足或 I/O 错误时，先停止新增操作、核查宿主文件系统及日志，排除原因后才人工恢复运行，禁止循环重启或自动修复唯一磁盘 [S4]。

- 每台配置固定且互不相同的 UUID、MAC 和 Windows 计算机名；每次启动复用，不随机重生成。两台分别安装，不复制已安装 Windows 的磁盘/TPM 身份。
- CODE 与 VARS 采用同一发行版提供的配套系列，例如 4M 系列与对应 Microsoft 密钥模板；“匹配”指配套布局，不要求两个文件字节数相等。VARS 只在首次创建时初始化，启动脚本不得反复覆盖；固件来源和 SHA-256 一并记录 [S8]。
- 明确使用哪种 VirtIO 控制器（virtio-blk 或 virtio-scsi），安装器加载与之匹配的驱动；额外挂载网卡驱动，确保 Windows 初始设置阶段可以联网。找不到磁盘或网卡时先解决驱动，不绕过安装要求。安装完后卸载安装 ISO、把系统盘设为首选启动设备，再验重启。
- 显示方案先通过安装器及系统桌面探针；记录实际显示设备、驱动、分辨率和软件渲染状态，不能把“能显示安装界面”当成完整图形兼容性证明。首期不包含 GPU 直通，也不据此承诺未来 GPU 工作负载可用。
- 启动脚本先检查路径、KVM 权限、空间、PID/锁和 socket；先拉起 swtpm，确认 socket 就绪，再启动 QEMU。QEMU 启动失败时仅回收此次启动的 swtpm 和临时运行文件，保留 TPM 状态及日志。拒绝覆盖已存在的磁盘；过期锁/PID 要核实进程身份后处理。
- `start`、`status`、`stop` 三个入口为最低交付要求；status 同时核对 PID、命令行和 QMP。正常 guest 重启应保持 QEMU 进程并重启系统，正常 guest 关机应退出 QEMU；不使用破坏该语义的 `-no-reboot`/`-no-shutdown`，也不让关机自动转为下一次开机。stop 等待正常退出，超时返回失败并保留日志；强制断电不作为日常关机路径。启动参数应保证关闭查看器不会误杀 VM，并实测查看器重连。
- 默认手动启动，不启用开机自启或后台常驻服务。宿主重启/关机前先正常关闭 guest；重新登录后通过 start 启动并复查。正常运行不让 guest 自动睡眠，避免控制台消失或误判关机；锁屏保持可用。宿主异常断电按第 7 节处理，不承诺自动恢复。
- QMP/swtpm/SPICE 控制 socket 均在 VM 私有目录，QMP 不监听公网。若 SPICE 改为本机 TCP，不能仅凭 127.0.0.1 当作用户认证，需配置访问认证并保护凭据；默认优先 UNIX socket。


## 5. 安装阶段与出口

| 阶段 | 实施动作 | 出口证据 / 失败处理 |
|---|---|---|
| P0 预检 | 重查资源、空间、端口；核对 ISO/许可；备份将修改的宿主配置 | 记录日期和版本；不满足门槛则暂不安装 |
| P1 宿主 | 安装 `qemu-system-x86`、`qemu-utils`、`qemu-system-gui`、`mtools`、`ovmf`、`swtpm`、`swtpm-tools`、`virt-viewer`；按需要补显示/音频后端包；将 arvin 加入 kvm 组并重新登录（或采用等效受控设备授权） | `/dev/kvm` 可读写、KVM API 与最小启动探针通过；不以 root 长期运行 VM |
| P2 固件与骨架 | 创建两个独立目录；配置固件、TPM、磁盘、NAT、控制台；启动安装介质 | QEMU 明确使用 KVM，固件/TPM 正常；参数不兼容先修正，禁止退到绕过安全要求安装 |
| P3 Windows | 分别安装、更新、装驱动（用户已决定任务完成后激活）；建立普通测试用户与独立管理账户；记录版本 | `Get-Tpm` 显示 TPM 就绪，Secure Boot 为 True，网卡/磁盘/显示无异常；重启后仍正常 |
| P4 基础配置 | 配置控制台、虚拟显示/声卡、普通用户权限和可选 RDP；记录系统/驱动/软件清单 | 两台均能交互使用；开发机与验收机均不安装项目工具 |
| P5 系统验收 | 按第 8 节检查设备、网络、开关机、路径、资源和访问范围 | 保存两台独立的验收记录；失败项修复后复验 |
| P6 重建演练与交付 | 在 clean 保存配置与样例数据，按清单重装并恢复样例；交付操作说明 | 系统可重建，样例校验一致；不依赖项目源码、构建或应用测试 |

### 5.1 分阶段准备与基础配置细节

1. **介质与包来源**：P0 记录 Windows 版本/语言/架构、ISO 官方来源及下载日期，核对官方公布的 SHA-256（自算 hash 只用于后续一致性，不能独自证明来源）。驱动检查发行渠道与签名。P1 更新软件索引并记录实际安装版本，优先同一 Debian 发行版的受维护包；如需 backports，先核查依赖，不盲目混装固件和 QEMU [S7]。
2. **图形与音频依赖**：显式安装 Debian `qemu-system-gui`，并核对所装 QEMU 的 display/audio/device 支持列表及 SPICE 后端。控制台用 `remote-viewer`，不假定直连 QEMU 能使用依赖 libvirt 的管理入口。音频首选经 SPICE 客户端传输并配置虚拟声卡；P4 实测播放、麦克风输入及重连。无输入设备时记录未执行，完整音频验收保持待完成 [S9]。
3. **Windows 初始设置**：安装前明确系统语言、键盘、时区（默认与宿主一致）、初始账户和密码保管方式；按官方流程完成联网设置，不把凭据写入脚本或日志。P3 记录激活状态即可；按用户最新要求，激活由用户在本任务完成后处理，不阻塞本次部署验收。
4. **更新与安全状态**：安装必要驱动后完成 Windows Update 及要求的重启，记录补丁、实际 build、系统时间和重启状态。Windows 时区与 QEMU RTC 基准要一致（首期采用 Windows 常用的本地时间 RTC 配置），开启系统时间同步，重启后核对时钟无明显偏差。保留 Defender、UAC 和 Windows 防火墙；不为连通性全局关闭防火墙。检查设备加密/BitLocker 实际状态，不能因未手工启用就认定未加密；如已启用，在固件变更或重建前确认恢复密钥可以从 guest 外取回，验收记录仅写保管位置和 key ID，不写密钥 [S10]。
5. **可选 RDP**：默认关闭，SPICE 为必须可用的管理通道。确需 RDP 时再安装宿主客户端、在 Windows Pro 中启用 RDP/NLA、授权指定账户并检查必要的 Windows 防火墙规则；QEMU 只做本机端口转发。仅配 hostfwd 不等于启用 RDP。使用两台时核对各自端口；未启用则验收标记不适用。
6. **实施输入清单**：P0 留存以上选择及管理员执行方式。许可/介质、账户、语言或客户端可用性尚未确定时明确标为待定，由实施时落实；不得在记录中假定已满足。先完成一台的固件/设备探针，再复用已验证的配置方法部署另一台。

固件候选现为 Debian OVMF 2022.11 系列；2026 年 Secure Boot 证书更新意味着不能仅凭包名判定兼容。实施时检查发行版固件修订、已注册密钥与最新官方安装介质是否匹配，必要时采用受维护来源的兼容固件；没有通过 P2/P3 不进入系统验收 [S6]。

## 6. 通用系统与未来复用

`win11-dev` 和 `win11-clean` 的名称、虚拟硬件及管理脚本与项目无关。本次两台仅安装 Windows、必要驱动、系统补丁和控制台所需组件，分别建立普通用户与管理账户。记录系统已有组件的实际状态，不人为卸载 Windows 自带组件。

后续开发环境搭建时再配置项目工作区、SDK、Git、编辑器和自动化服务。未来项目可复用两台 VM，无需按项目自动新建机器；如需要不同系统或互斥依赖，再单独评估资源。clean 的“干净”指有明确的系统和软件清单；跨项目留下的机器级依赖不能靠新建用户消除，需要全新系统时按重建清单重新安装。

### 当前用户权限与执行分工

| 操作 | 执行权限与当前状态 |
|---|---|
| 安装宿主虚拟化软件、配置 KVM 组权限 | 需宿主管理员；arvin 在 sudo 组，但只读 `sudo -n -l` 返回需要密码，尚未验证认证后的具体授权范围 |
| 创建 `/data/vm` 下的 VM 目录和文件 | arvin 当前可写，可由普通用户执行 |
| 日常启动/关闭 QEMU 与 swtpm | KVM 权限配置并重新登录验证后，以 arvin 运行，无需长期 root |
| 安装 Windows 驱动/系统级组件 | 使用 Windows 内的管理员账户，与宿主 arvin 权限独立 |
| 用户态 NAT 和本机高位端口转发 | 按本计划无需配置宿主网桥或修改系统防火墙 |

P1 的管理员步骤须由有权限的操作者在本机终端完成；不要求通过对话发送密码。权限准备不足时停在 P1，不以软件模拟替代 KVM 验收。

## 7. 关键数据备份与环境重建

### 7.1 备份范围

| 数据 | 保存方法与时机 |
|---|---|
| VM 启动参数、驱动版本、介质来源/hash、安装步骤 | 配置变更时导出到 `backups/critical/`，不包含密码 |
| 系统验收记录、手工配置和不可再生成的用户文件 | 重要变更或重建前导出；保留最新两份小体积有效导出 |
| BitLocker 恢复密钥（若启用） | 单独存入用户受控的加密保管位置，不能只留在 guest 系统盘 |
| 系统镜像、可重新下载的安装介质、普通日志和缓存 | 不备份，可重新安装或获取 |

`backups/critical/` 是本机恢复暂存，仍在 `/data/vm/<vm>/` 内。同盘副本不防整盘故障；不可再生成的唯一数据还需保存在用户受控的离机位置。本次不创建外部存储服务或上传数据。关键导出总预算 10 GiB，超限时审查范围，不扩成整机备份。

TPM/Windows 身份绑定的密文不能仅靠复制文件迁移到新系统；若保存了这类数据，重建前需使用对应功能支持的可迁移导出。BitLocker 恢复密钥用于解锁原磁盘，不等同于恢复所有用户凭据。不单独恢复旧 VARS/TPM 去拼接新装 Windows；重建使用新的匹配状态与身份，按许可要求重新激活。

### 7.2 数据导出通道

本计划默认不共享宿主目录，需提供独立的关键文件传输方法。使用每台 `transfer/` 下的小容量可写 FAT 交换镜像（首期 256 MiB，raw 格式并初始化 FAT 文件系统，计入 40 GiB 杂项预算），作为临时 USB 存储设备附加给 guest。guest 复制待导出文件后正常关机，QEMU 完全退出后，宿主使用 mtools 读取镜像并将文件写入 `backups/critical/`；导入则反向操作。宿主和 guest 不得同时写镜像，不直接挂载正在使用的系统盘 [S11]。

首次创建交换镜像只针对尚不存在的新文件，使用 mtools 初始化并记录采用的文件系统布局；若使用分区，记录 mtools 读取所需的分区偏移。配置独立的虚拟 USB 控制器和 USB 存储设备，先确认 Windows 能识别且可写，再用于备份；不在安装器选盘时挂入交换盘，避免格式化错盘。镜像默认不挂载，只有传输模式才附加；导入已有镜像时不得重新格式化 [S11]。

该通道用于配置、记录与小样例文件；FAT 单文件限制或容量不足时先调整传输方案，不能截断文件。传输前后比较 SHA-256，敏感导出需先加密；使用后解除挂载并清理已确认可删除的交换内容。P6 用无敏感信息的小样例完整执行导出→重装→导入→校验。

### 7.3 重建流程

1. 确认需要保留的用户数据和关键配置已导出且重建后可获取；已有其它数据时先处理，不自动删除。先将导出恢复到临时目录并校验文件清单、SHA-256 和可读性；加密导出需实际验证解密，不能仅因压缩包存在就删除原数据。验证失败时不进入重装。导出记录和解密材料不能只留在将被重置的系统盘中。
2. 正常关机并停止 QEMU/swtpm，停止所有使用该 VM 的任务。操作严格限定目标 VM 目录，检查真实路径，防止误操作另一台机器。
3. 只有 P6 的无敏感样例环境或已明确选定重建目标时才执行重置。记录目标 VM 名、磁盘路径和需重置的文件清单，与普通 start 分开；正常启动不触发重装。按记录的官方介质、虚拟硬件和驱动清单重新安装，建立新的磁盘/固件变量/TPM 配套状态。不保留完整旧磁盘作为例行备份；异常磁盘需要诊断时单独评估暂存空间，不自动复制整盘或执行有损修复。
4. 重新安装系统驱动与补丁，建立账户和控制台连接；恢复适用的关键配置及用户文件。
5. 验证 P3、数据可读性与第 8 节系统验收项，记录新的配置基线和实际软件清单。首次实施在 clean 做一次重建演练，确认这条恢复路径有效。重装仅重置 disks/firmware/tpm 的系统状态，不删除 config/backups/transfer/evidence；恢复前校验导出文件。

系统损坏或需要全新系统时通过重装恢复，不保证保留原 Windows/TPM 身份。日常系统及驱动更新后复查启动、网络与基础设备，更新重建清单；不要求更新前复制磁盘。镜像、TPM 与关键导出限制为机主访问，验收记录不包含密码或恢复密钥。

## 8. 安装部署验收标准

| 检查项 | 完成条件 |
|---|---|
| 权限与加速 | arvin 能以普通用户启动两台 VM；运行配置确认 KVM 加速，无软件模拟回退 |
| Windows 与固件 | 官方安装完成，记录版本和激活状态，允许待激活交付；TPM 2.0 就绪，Secure Boot 为 True |
| 基础设备 | 设备管理器无未解决的驱动异常；磁盘、网卡、显示、键鼠正常；音频播放/输入按配置实测 |
| 网络与访问 | guest 能解析域名并访问更新服务；控制台可用；RDP 未启用时标记不适用；启用时按设定本机端口连接成功且 guest 账户授权有效 |
| 生命周期 | 两台分别正常重启、关机、再次启动；无重复写盘或遗留 swtpm 进程；配置重启后仍生效 |
| 目录与资源 | VM 专属文件、状态及日志位于各自目录；核对文件实际路径及资源余量 |
| 重建能力 | clean 按清单重装成功；配置和样例数据导出恢复后校验一致；无整机备份依赖 |
| 交付材料 | 两台的启动/停止方法、版本/校验和清单、权限说明及脱敏验收记录完整 |

两台都满足上述标准即完成本次部署。应用构建、项目功能测试和发布结果不参与本次判定。

**实施结论：两台 Windows 11 虚拟机已安装、更新并完成系统运行验收；clean 已完成重建与样例恢复演练。激活按用户要求留到本任务结束后由机主处理。具体结果与证据见部署记录。**

### 8.1 验收证据与未通过项

每项写明 VM 名、配置版本、执行时间、实际结果和证据文件；状态为通过/失败/未执行/不适用。不适用只用于明确可选项，例如关闭的 RDP；不能把缺设备导致的未执行填成通过。记录 `Get-Tpm`、`Confirm-SecureBootUEFI`、`manage-bde -status` 的必要结果及设备清单；敏感输出脱敏。KVM 使用运行时 QMP 查询与启动日志核实，不仅检查命令行写了 `-accel kvm`。每台至少验证一次正常重启与一次关机后重新启动，clean 重建后重复检查。故障验收仅使用临时配置或小型测试文件：验证错误挂载标识、重复启动和启动依赖失败均被拒绝，且原磁盘/TPM 未被覆盖；磁盘错误分支用独立小型测试镜像或受控模拟验证，不写满真实 /data，也不破坏实际系统盘。导出恢复校验必须先于 clean 重装。

交付的脚本说明还须列出失败退出码、日志路径和人工恢复步骤。实施后两台的 `config/README.txt` 与[部署记录](WINDOWS-VM-DEPLOYMENT.md)给出命令与恢复说明；重复启动、错误存储 UUID、内存不足、缺少安装介质的拒绝，以及独立 8 MiB 镜像注入 I/O 错误后的 QMP `io-error` 暂停已分别取证。历史方案审阅不替代这些运行证据。
